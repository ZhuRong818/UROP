## 2026-08-29 — Comprehensive Lumid Studio/FinData usability audit

- The in-app browser service was unavailable, so no click-level UI claim is made. The
  public Studio shell was fetched successfully (HTTP 200, title `Lumid Studio`) and
  returned an authentication shell. The live OpenAPI was also fetched and classified.
- Catalog discovery exposed 13 schemas and 178 tables. Catalog metadata itself is
  anonymously readable (HTTP 200), while Studio authentication is required for the
  interactive shell. MCP `tools/list` returned 90 tools.
- 157/178 table profiles returned both profile and JSON schema. Nineteen large-table
  profile calls timed out at a 30-second ceiling, including `news.articles`, KOL tweets,
  market OHLC, prediction-market trades/orderbooks and Kalshi market tables. Two
  materialized-view schema routes returned 404 (`fundamentals.latest_per_symbol` and
  `reference.active_symbols`).
- `news.articles` is a concrete catalog inconsistency: `information_schema` exposes 22
  columns (`id`, `ingest_ts`, source/endpoint/run provenance and `search_tsv` included),
  but the Studio JSON schema exposes only 16 and omits those six fields. Its catalog
  listing also reports zero estimated rows despite the populated warehouse.
- Read-only `/retrieve` supports JSONL and CSV, CTE/window SQL, empty results and a
  1,500-row materialization. Parquet is rejected, `/retrieve` is absent from OpenAPI,
  and an unbounded full-table news FTS query exceeds 30 seconds; the same FTS query
  completes immediately when bounded to the EventX date window. No DDL/DML was issued.
- Lineage is usable when its natural key is supplied: `news.articles?id=240598138`
  returned source/run provenance. The documented-looking no-key call returns 400, and
  `/catalog/lineage/runs` currently returns zero runs. This is an interface/documentation
  limitation, not a total lineage failure.
- 28/28 representative REST probes returned 2xx with no timeouts: news latest/search,
  KOL list/archive/search, prediction-market events/search/details/trades/candles,
  Kalshi orderbook, Polymarket open interest, quotes, OHLC, fundamentals, macro,
  health/status/freshness. Two valid endpoints returned empty data for the selected
  samples: Kalshi open-interest and Polymarket orderbook.
- Practical conclusion: Studio/FinData is usable for EventX bounded read extraction,
  JSONL/CSV export, prediction-market trades/candles and news/KOL search. It is not
  reliable as the sole catalog/provenance contract, is slow for unbounded/large-table
  interactive queries, has no Parquet export, and currently provides sparse news
  coverage for the frozen event-market cohort. Preserve SQL, receipts,
  `information_schema` checks and hashes for every export.
- Reports: `data/v2_3_1/lumid_studio_audit_20260829/report.json` and
